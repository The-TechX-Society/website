# Issues Checklist
- [ ] Is the description clear and concise (especially the intended outcome)? Doubly so if intended to be taken by another developer.
- [ ] Is all necessary context provided to reasonably complete the issues?
- [ ] Did you include appropriate tags for ease of search?

# PR Checklist

- [ ] Does your code actually complete the issue? (i.e. fulfills all acceptance criteria)
- [ ] Did you thoroughly test the feature locally + it works as expected?
- [ ] Does your code build?
- [ ] Is your code formatted?

If so, go ahead and assign a reviewer to this PR, which will typically be a member of exec (if you aren't sure who should be reviewing your PR, it's ok to just pick someone arbitrary -- we can redirect if necessary).

Once approved, your PR is good to merge.
